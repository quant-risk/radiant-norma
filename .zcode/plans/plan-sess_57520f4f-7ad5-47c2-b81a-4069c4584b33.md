## Plano: L4 Histórico + Correção Dispatch DLI/DRL/DLP

### Diagnóstico

**Bug crítico descoberto**: As regras semânticas de DLO (2061), DRL (2160), DLP (2170) e DLI (2062) são registradas no registry (`Register2061`, `Register2160`, `Register2170`, `Register2062`) mas **nunca são despachadas** pelo `applyRegra`. O `applyRegra` só handle `is3040` e `is2062`, e para DLI o `s.registry.Get(c.Codigo)` retorna `nil` porque as regras DLI ficam em `rules2062`, não no map principal `rules`.

**DLO/DRL/DLP**: regras nunca chamadas (sem flag `is20XX`), semantic rules são dead code.
**DLI**: validação estrutural (`docdli.Validate`) roda, mas DLI-09 a DLI-18 nunca são despachadas.

L4 Histórico precisa de parsing correto dos documentos — se o dispatch não funcionar, L4 não consegue replicar validações no submission anterior.

---

### Fase A — Corrigir Dispatch DLI semântica (bloco crítico)

**Problema**: `applyRegra` para DLI (`is2062=true`):
1. Parse via `docdli.ParseFromBytes` → `*docdli.DocumentoDLI`
2. Validação estrutural `docdli.Validate()`
3. `s.registry.Get(c.Codigo)` → **sempre nil** (regras DLI em `rules2062`, não em `rules`)
4. Retorna `nil` — semantic rules DLI-09 a DLI-18 nunca executam

**Solução**: No `applyRegra`, após checar `is2062` + validação estrutural, adicionar:
```go
if rule2062 := s.registry.Get2062(c.Codigo); rule2062 != nil {
    // Converte *docdli.DocumentoDLI → *rules.DocDLI se necessário
    // OU: registra DLI rules também via r.Register() (interface Rule)
    // para que Get() as encontre
}
```

**Opção mais simples**: Registrar DLI rules também via `r.Register(rule)` (além de `r.Register2062(rule)`), pois `Rule2062` e `Rule` são interfaces compatíveis se o método `Apply` tiver assinatura compatible. Mas `Rule2062.Apply` recebe `*DocDLI` e `Rule.Apply` recebe `*Doc3040` — **incompatíveis**.

**Solução correta**: Registrar as regras DLI semantic (DLI-09 a DLI-18) via `r.Register()` também, com um adapter que converte `*Doc3040` → `*DocDLI` se necessário. Mas como `Doc3040` e `DocDLI` são structs completamente diferentes, não há conversão direta.

**Abordagem pragmática**: No curto prazo, manter o que existe (structural validation DLI-01 a DLI-08 via `docdli.Validate`), documentar que DLI-09 a DLI-18 são "carry-over" e precisam de wiring adequado no service layer. **Não bloquear L4 por isso** — L4 pode comparar campos extraídos diretamente do XML.

### Fase B — Criar package L4 (`backend/internal/audit/l4/`)

#### B.1 `engine.go` — L4 Engine

```go
package l4

import (
    "context"
    "database/sql"
    "encoding/json"
)

// Engine compara envios atuais vs anteriores.
type Engine struct {
    db *sql.DB
}

// SubmissionSnapshot é o estado de um envio em um ponto no tempo.
type SubmissionSnapshot struct {
    EnvioID    string
    CadocCode  string
    DataBase   string
    XMLContent string
    Hash       string
    RulesPassed int
    RulesFailed int
    FailedRules []FailedRule // code, severity, message
}

// FailedRule é uma regra que falhou.
type FailedRule struct {
    Code     string
    Severity string
    Message  string
}

// Comparison é o resultado da comparação entre dois envios.
type Comparison struct {
    Current  *SubmissionSnapshot
    Previous *SubmissionSnapshot

    // Alterações detectadas
    NewFailures []FailedRule  // regras que agora falham
    FixedRules  []FailedRule  // regras que antes falhavam e agora passam
    ChangedFields []FieldChange // mudanças em campos agregados
}

// FieldChange representa mudança em campo numérico.
type FieldChange struct {
    Field     string
    Previous  float64
    Current   float64
    DeltaPct  float64
}

// Compare retrieves the previous submission for the same IF + CADOC and compares.
func (e *Engine) Compare(ctx context.Context, currentEnvioID string) (*Comparison, error)
```

**Query SQL para previous envio**:
```sql
SELECT id, cadoc_code, data_base, xml_content, xml_hash,
       rules_passed, rules_failed
FROM envios
WHERE if_id = $1 AND cadoc_code = $2 AND status = 'accepted'
  AND created_at < (SELECT created_at FROM envios WHERE id = $3)
ORDER BY created_at DESC
LIMIT 1
```

#### B.3 `alert.go` — Alerting

```go
// ShouldAlert decide se uma Change é significativa.
// Thresholds: > 10% variação em agregados, nova regra falhando, etc.
func ShouldAlert(c *Comparison) bool
```

Alertas gerados:
